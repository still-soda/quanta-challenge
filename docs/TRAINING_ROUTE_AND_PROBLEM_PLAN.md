# 培训路线调整建议 × 平台出题可行性分析

分析依据（2026-10 收到的四份材料）：

| 材料 | 规模 | 性质 |
|---|---|---|
| `2025年前端培训路线.docx` | 8 周安排，共 23 段 | 现行教学计划 |
| `前端小册子2026(1).docx` | 256 段、约 2.9 万字 | 二面备考讲义（含 AI 工具介绍） |
| `Quanta2025前端二面笔试试卷（考生版）.docx` | 10 单选 + 5 多选 + 5 简答 + 2 手写 | 现行考核方式 |

---

## 一、先说结论

1. **路线本身结构是合理的**（HTML → CSS → 布局 → 动画 → JS → DOM），但**缺少"表单/表格/链接"这一块**，
   而它恰好是笔试与手写题的**最高频考点**（10 道单选里至少 4 道、5 道多选里 2 道、2 道手写题的命题范围）。
2. **JS 与 DOM 应当合并**。现在 JS 在第 6–7 周、DOM 在第 8 周，等于把"语言"与"用它做事"割开两周；
   合并后第 8 周可以做完整小作品，学习闭环更完整。
3. **讲义里的"调试与开发者工具"没有进入路线**，但对零基础学员是**最高杠杆**的一项（讲义反复强调）。
4. **平台能自动判的是"代码题"，不能判讲义里的概念题、AI 编程（Vibe coding）内容。**
   建议明确分工：**线上实训给代码题、线下笔试保留概念题**，不要试图把选择题搬上平台。
5. 按下面第五节清单补题，可覆盖路线 8 周里的 **7 周**（第 1–8 周，除纯环境搭建部分），
   且与笔试考点形成互补而非重复。

## 三、平台能判什么、不能判什么（这决定出题的边界）

### 判题能力（实测确认）

判题脚本每个检查点拿到的是**完整 Playwright `Page`**（仅屏蔽 `goto`），因此可以断言：

| 能力 | 能否 | 说明 |
|---|---|---|
| DOM 文本 / 属性 | ✅ | `page.$eval(el => el.textContent)` |
| **计算样式** | ✅ | `page.$eval(el => getComputedStyle(el).color)` → **CSS 题可判** |
| 交互（点击/输入/悬停） | ✅ | 注意：`disabled` 按钮要用派发合成事件，否则 Playwright 卡 30s |
| 视口与响应式 | ✅ | 脚本内 `page.setViewportSize(...)` 可测媒体查询 |
| 截图比对 | ⚠️ 可用但脆 | 审计时存首屏截图，judge 模式用 Jimp 算相似度；**像素级比对对字体/抗锯齿极敏感**，不建议作为主要手段 |
| 纯选择题 / 简答题文本 | ❌ | 平台是代码判题，没有选择题题型 |
| 概念理解（如"前后端分离"） | ❌ | 无法自动判分 |
| AI 编程 / 提示词 | ❌ | 无法判分 |
| `<input type="file">` 等真实文件操作 | ⚠️ | Playwright 可支持，但题目设计会很别扭 |

### 结论

- **能出题（且有用）**：HTML 结构 / CSS 样式 / 布局 / 动画 / JS 基础 / DOM 事件 —— 路线第 1–8 周几乎全部覆盖
- **不适合出题**：概念题（静态 vs 动态页面、HTTP 流程、前后端分离）、AI 工具使用
- **建议分工**：平台负责"**动手写出来**"，笔试负责"**说得清为什么**"

## 四、调整后的路线建议（8 周）

在原结构上做**最小改动**，只调整两处 + 补一个模块：

| 周次 | 原安排 | 建议安排 | 变更理由 |
|---|---|---|---|
| 1（10/18-19） | 环境搭建 + 初步接触 HTML5 | 环境搭建 + **F12 调试入门** + HTML 基础 + **表单 / 表格 / 链接** | 补最高频考点；第一天就能做出"登录表单"，比静态页更有成就感 |
| 2（10/25-26） | CSS 语法 + 选择器 + 层叠 | **不变**（建议练习加"选择器优先级猜结果"） | 笔试单选第 5 题、多选第 4 题在此 |
| 3（11/1-2） | 盒模型与视觉样式 | **不变** | —— |
| 4（11/8-9） | Flex + Grid + 媒体查询 | **不变** + **产出小作品：响应式卡片列表** | 补"阶段性作品" |
| 5（11/15-16） | 过渡 / 动画 / 变量 | **不变**（加"主题切换"小练习） | —— |
| 6（11/22-23） | JS 基础 + BOM | JS 基础 + BOM + **DOM 选择与读取** | 提前引入 DOM，不再割裂 |
| 7（11/29-30） | 函数 + 定时器 | 函数 / 作用域 + 定时器 + **DOM 修改与事件绑定** | 同上 |
| 8（12/6-7） | DOM 操作与事件 | **综合实战** + 产出小作品（列表增删 / 购物车） | 收口，形成完整闭环 |

**两处核心变更**：
1. 第 1 周并入 **表单/表格/链接 + F12 调试**（补笔试高频考点）
2. 第 6–8 周把 **DOM 提前**，让 JS 与"用 JS 操作页面"连成一体

## 五、配套题目清单（按优先级）

优先级依据：**笔试考点重合度 × 学员动手可行性 × 判题实现成本**

### P0 — 建议立即补（与笔试强相关，且第 1 周就要用）

| 题目 | 考点 | 难度 | 可判性 |
|---|---|---|---|
| **1. 语义化个人名片页** | 文档结构、标题层级、`<img>` + `alt`、列表 | easy | 强（DOM 断言） |
| **2. 登录表单** | `<form action method>`、`<input type>`（text/password/submit）、`required`、`<label>` 关联、行内样式、尺寸/居中/边框 | medium | 强（DOM + computed style） |
| **3. 表格：课程表** | `<table>/<thead>/<tbody>/<tr>/<th>/<td>`、`thead` 与 `tbody` 分组 | easy | 强 |
| **4. 链接与打开方式** | `<a href target="_blank" rel="noopener">` | easy | 强 |

> 这 4 道题直接对应笔试单选 2/3/4/9、多选 1/3/5、简答 2/3/4/5、手写 1/2。
> **手写题 1（登录表单）与手写题 2（表格）几乎可以原样搬上平台**，只是把"纸笔写代码"变成"线上写代码 + 自动判分"。

| 题目 | 考点 | 难度 | 可判性 |

### ❌ 不建议做成平台题（无法判分或有更好载体）

- 纯视觉设计题（"做得好看"）→ 截图比对太脆，容易误判；若要考，改用**结构 + 计算样式**断言

## 六、工作量与实施建议

1. **先补 P0 的 4 道题**（第 1 周就要用），预计每题 15–25 分钟（写参考解 + 判题脚本 + 预检 + 上传）
2. **P1/P2 按周推进**，每周主讲经理负责当周的 2–3 道题，与备课同步产出
3. **出题必须走预检**（详见 `docs/PROBLEM_AUTHORING.md`）：参考解满分、答案模板低分，两者都要跑
4. **判题脚本优先用 DOM + 计算样式断言，不要用截图比对**；截图仅作审计封面
5. **线上题与线下笔试明确分工**：平台考"写得出"，笔试考"说得清"，互为补充而不是重复

---

## 七、一句话总结

> 路线骨架没问题，缺的是**表单/表格/链接**（笔试最高频）与**调试入门**，
> 而 JS 与 DOM 应该合并。
> 平台上**凡是"能动手写出来"的都能出题且很有用**（HTML/CSS/布局/动画/DOM 全覆盖），
> **凡是"要说得清"的概念题与 AI 编程内容则不适合**，应留给线下笔试与阅读材料。
